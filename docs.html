1 · 安装与权限

从下载到第一次呼出面板，大约 5 分钟。

系统要求

  • macOS 15 或更高版本（Apple Silicon / Intel）
  • CodeVault 是菜单栏应用：启动后不出现 Dock 图标，常驻屏幕顶部菜单栏

安装步骤

  1. 从官方 Releases 页面下载 .dmg，把 CodeVault 拖入「应用程序」文件夹后启动。

  2. 如提示「无法验证开发者」：前往 系统设置 → 隐私与安全性，底部点「仍要打开」。

  3. 首次启动进入引导流程：欢迎页 → 权限页 → 完成。

  4. 授予辅助功能权限（全局快捷键所需）：引导页点「授权」，系统会打开 系统设置 → 隐私与安全性 → 辅助功能，在列表中打开 CodeVault 的开关。

  5. 回到引导页确认状态变为「已授权」，按 ⌘⌥K 试试呼出快捷面板。完成。

权限边界

辅助功能权限只用于两件事：注册全局快捷键、把片段「写入」其他应用的输入框。CodeVault 不会监控你的键盘输入内容。权限刚授予时如快捷键无响应，重启一次 CodeVault 即可。

2 · 创建第一条条目

入库 30 秒，之后每天取用 3 秒。

  1. 点击菜单栏的 CodeVault 图标 → 打开 CodeVault（主窗口）。

  2. 点右上角 + 新建条目。

  3. 填写：标题（如 pg_conn_dev）、类型（四选一，见下一章）、语言（代码类）、内容，标签可选（输入回车添加，如 db、常用）。

  4. 保存。

三步取用闭环（核心）

现在到任意应用——终端、浏览器、编辑器都行：

  1. 按 ⌘⌥K 呼出快捷面板

  2. 输入两三个字母，比如 pg

  3. ↑↓ 选中 → ↩ 复制并关闭面板 → ⌘V 粘贴

这一套就是 CodeVault 的核心闭环，也是你每天会重复 30+ 次的动作。

最重要的习惯

保存条目时起一个可搜索的好标题（pg_conn_dev 而不是「连接1」），两三个字母即可命中。搜索匹配标题、语言、标签。

3 · 快捷面板

不切应用的浮动面板：搜索 → 选中 → 取用。键盘优先。

打开与关闭

  • 打开 / 关闭：⌘⌥K（默认，可自定义，见设置参考）
  • 关闭：esc，或点击面板外任意位置
  • 面板可在任何应用前台呼出，包括全屏应用；多显示器下出现在当前活跃的屏幕

搜索

  • 匹配范围：标题、语言、标签
  • 最近使用优先：不输入时显示「最近使用」，输入后按相关度排列
  • 类型过滤：面板顶部类型筛选（全部 / 代码 / 提示词 / 笔记 / 密钥）
  • 主窗口（非快捷面板）内的搜索快捷键是 ⌘K

键盘操作

按键作用
↑ ↓在结果间移动
↩复制选中条目并关闭面板
双击条目「双击写入」开启时：写回原应用的光标处（见下）
esc关闭面板

双击写入

设置项：主窗口 → 设置 → 双击写入。

  • 关闭时：双击条目 = 复制内容，你自己在目标应用里 ⌘V
  • 开启时：若打开面板前有可编辑文本框处于焦点（终端、编辑器、聊天输入框……），双击会直接把内容写入该输入框，同时保留一份在剪贴板

适合终端里频繁粘命令、聊天工具里频繁发模板的场景。注意写入依赖辅助功能权限。

自定义容器布局

搜索是通用路径，但你最高频的那十几个条目值得更快的直达——容器（Container）可以把它们固定成专属布局：

  1. 面板右侧切换到 自定义 标签

  2. 点击 进入编辑 → 新增容器，给容器起标题（如 DB 日常）

  3. 在左侧搜索结果中选中条目，点 添加 放入当前容器

  4. 拖动片段在容器内重排、跨容器移动；拖容器右下角调整尺寸

  5. 完成后点 完成编辑。浏览态只展示干净的结果，编辑控件全部隐藏

  • 一个容器放同一场景的片段（如「部署命令」「常用 prompt」），打开面板不用搜索直接点
  • 顶栏显示布局摘要：N 个容器 · M 个 Snippet
  • 编辑态支持清空与删除单个容器；布局数据随条目库一起同步 / 备份
使用建议

搜索为主，容器为辅：先靠搜索跑一段时间，发现每天都要搜的条目，再固化进容器。最近使用本身就是智能排序，无需手动置顶。

4 · 条目与四种类型

类型决定字段与取用行为。按技术工作者的真实资产分类。

代码Code

函数片段、SQL、配置模板、shell 命令。按语言高亮。

提示词Prompt

LLM 提示词、邮件模板、回复话术，随取随改。

笔记Text

排错记录、环境说明、速查清单。记「为什么」。

密钥Key

API token、连接串、内网地址。AES-GCM 加密，掩码显示。

选类型的判断法：会用第二次的进片段库；别人给你但你还要发出去的模板是提示词；泄露了要出事的是密钥。

字段说明

  • 标题：搜索的第一匹配对象，推荐「可前缀检索」的命名
  • 语言：仅代码类型需要，影响编辑器与预览的高亮
  • 实现备注：写给自己看的上下文——这个片段哪来的、什么时候用、有什么坑
  • 标签：多个短词，输入回车添加；侧边栏「标签」区按标签聚合，点击即过滤

推荐一套自己的短标签体系：db、deploy、llm、work……避免「同一个概念两个标签」。

密钥类型与加密

  • 密钥条目的敏感字段使用 AES-GCM 本地加密存储，密钥由应用派生管理
  • 登录凭据、同步 Token 只存 Keychain，不落普通文件
  • 面板与列表中密钥内容掩码显示，取用与正常条目一致（复制 / 写入）
  • 加密保护的是静态存储：同步开启后，密文会随数据集同步到你的服务端
安全提醒

CodeVault 不替代密钥轮换。生产凭证定期轮换、开启系统 FileVault，比任何单一工具都重要。

编辑器

  • 创建 / 编辑在主窗口的编辑器中进行，支持自动换行开关、语言高亮
  • 编辑已有条目：保存更改 生效；放弃 恢复原样
  • 条目卡片上直接复制内容，不用进编辑器

5 · 剪贴板模块

被动记录 + 主动收纳：自动保存复制历史，一键入库。

打开剪贴板面板

  • 默认快捷键 ⌘2（可自定义）
  • 菜单栏 → 剪贴板 → 显示历史
  • 设置中开启「在菜单栏显示」后，可常驻一个独立菜单栏图标

历史面板能做什么

  • 回取任意历史：↑↓ 或点击选择，重新放入剪贴板
  • 直接粘贴：开启后，从历史中选中即自动粘贴到当前光标处（依赖辅助功能权限）
  • 置顶：高频内容置顶不会被滚动冲走；清空历史时置顶项保留
  • 标签：给历史项打标签分组；支持添加到标签 / 移除所有标签
  • 来源应用：每条历史显示复制时所在的应用图标

设置项一览

设置说明
启用剪贴板管理总开关；关闭即完全停止记录
直接粘贴选中历史项后自动粘贴（而非仅复制）
纯文本粘贴粘贴时剥离富文本样式，只保留纯文本
历史容量保留多少条历史记录
保留时间天 / 周 / 月 / 不限，超期自动清理
网格行数历史卡片在窗口与底部面板中的显示密度
iCloud 同步剪贴板历史经你自己的 iCloud 同步，需显式开启

存入片段库（被动 → 主动）

复制来的内容一旦确认常用，别让它留在历史里：

  1. 打开剪贴板面板，找到目标历史项

  2. 点 存入 CodeVault

  3. 系统自动识别类型并生成初始标题，在编辑器里确认 / 修改后保存

日常节奏

先复制、后整理——白天随手复制不中断工作，晚上花两分钟把有价值的存入片段库并起好标题。

6 · 多设备同步

本地优先：不登录就是纯本地应用。登录后每 5 分钟自动同步。

登录

菜单栏 → Sign In，填写两项：

字段说明
服务地址同步服务端域名，如 https://sync.example.com（官方服务或你自部署的 Worker）
API Token服务端发放的访问凭证；只保存在本机 Keychain

Token 从哪来（二选一）：官方服务在网页门户注册 → 创建应用 → 生成 Token（明文只显示一次）；自部署则在部署时生成，见下一章。

同步怎么工作

登录后，App 每 5 分钟自动同步一次，也可手动触发立即同步：

# 每次同步 = 一读一写，内容无变化则跳过写回
App ── GET  全量数据 ──▶ 服务端
App ◀── 服务端全集 ────
        本地合并（last-write-wins）
App ── POST 合并结果 ─▶ 服务端
  • 同步范围：片段库条目（含标题、类型、语言、内容、备注、标签、容器布局）
  • 单应用数据上限 24MiB（纯文本场景几乎不可能触顶）

冲突规则（透明可预期）

情况结果
两台设备改了不同条目都保留
两台设备改了同一条目updatedAt 新者胜出（last-write-wins）
一端删除、另一端未动删除生效
删除后另一端离线期间改了同一条目近 7 天内的删除有墓碑记录，条目不会复活
换机 / 重装

登录同一服务地址 + Token，首次同步会把服务端全集拉回本机，无需手动迁移。退出登录后本机数据保留，仅停止同步。

Token 安全

Token 泄露后：官方服务在门户吊销 Token；自部署则重设 Token（旧值立即失效），见自部署的运维一节。

7 · 自部署同步服务

不想用任何第三方同步服务？10 分钟把同步后端部署到自己的 Cloudflare 账号。

你会得到什么

  • 一个 https://<你的子域>.workers.dev 的同步端点（可绑定自定义域）
  • 一个你自己生成的全局 Token：所有设备填同一组「服务地址 + Token」即同步
  • 数据存储：Cloudflare Workers KV，免费额度足够个人多设备使用

前置条件

一个 Cloudflare 账号（免费版即可）+ 本机有 Node.js（运行 wrangler CLI）。

部署六步

# 1. 进入仓库的 sync-worker 目录
cd sync-worker

# 2. 安装依赖（wrangler CLI）
npm install

# 3. 登录 Cloudflare（浏览器授权）
npx wrangler login

# 4. 创建 KV 存储，把输出里的 id 填进 wrangler.toml
npx wrangler kv namespace create SNIPPETS

# 5. 生成你的专属 Token（记下来，只显示这一次）
openssl rand -hex 32

# 6. 配置 Token 并部署
npx wrangler secret put SYNC_TOKEN
npx wrangler deploy

部署完成会输出服务地址。App 端接入：菜单栏 → Sign In → 服务地址填上面的域名，Token 填第 5 步生成的值，多台设备填同一组即可。

日常运维

操作命令 / 说明
更新部署改完代码后 npx wrangler deploy
作废旧 Tokennpx wrangler secret put SYNC_TOKEN 生成新值，所有设备改填
本地开发调试cp .dev.vars.example .dev.vars && npm run dev → http://localhost:8787
运行测试npm test（89 个功能测试，纯本地无需部署）

进阶：对外提供服务（可选）

同一 Worker 还支持「官方服务模式」，给家人 / 朋友 / 团队开账号：

  • 设置 ADMIN_PASS 后，GET / 变成用户门户网页（注册 / 登录 / 管理应用与 Token）
  • 配齐 RESEND_API_KEY + RESEND_FROM 可启用邮箱验证码注册
  • 管理员可在门户删除用户（级联清理其全部应用、Token 与数据）

完整配置与架构说明见 sync-worker/README.md 与 DEPLOY.md。

限制与权衡

单应用数据集上限 24MiB（Workers KV 单值限制）；冲突由 App 端按更新时间新者胜出，服务端不解析内容；Workers KV 为最终一致（跨节点 ≤60s）。

1 · Install & permissions

From download to your first panel summon in about five minutes.

Requirements

  • macOS 15 or later (Apple Silicon / Intel)
  • CodeVault is a menu-bar app: no Dock icon after launch — it lives in the menu bar at the top of your screen

Install steps

  1. Download the .dmg from the official Releases page, then drag CodeVault into Applications and launch it.

  2. If macOS says the app “can't be verified”: go to System Settings → Privacy & Security and click “Open Anyway” at the bottom.

  3. First launch opens the onboarding flow: Welcome → Permissions → Done.

  4. Grant the Accessibility permission (required for global hotkeys): click “Grant” in onboarding, which opens System Settings → Privacy & Security → Accessibility; turn on the switch next to CodeVault.

  5. Back in onboarding, confirm the status shows “Granted”, then press ⌘⌥K to summon the quick panel. Done.

Permission scope

The Accessibility permission is used for exactly two things: registering global hotkeys and “typing” snippets into other apps' text fields. CodeVault does not monitor what you type. If hotkeys don't respond right after granting permission, restart CodeVault once.

2 · Create your first item

30 seconds to store it, 3 seconds every day after.

  1. Click the CodeVault icon in the menu bar → Open CodeVault (main window).

  2. Click + New Item in the top-right corner.

  3. Fill in: title (e.g. pg_conn_dev), type (one of four, see the next chapter), language (for Code items), content; tags optional (type and press Return, e.g. db, frequent).

  4. Save.

The three-step retrieval loop (the core)

Now switch to any app — Terminal, a browser, an editor:

  1. Press ⌘⌥K to summon the quick panel

  2. Type two or three letters, e.g. pg

  3. ↑↓ to select → ↩ to copy and close → ⌘V to paste

That's the core CodeVault loop — the action you'll repeat 30+ times a day.

The single most important habit

Give items searchable titles (pg_conn_dev, not “conn 1”) so two or three letters hit the target. Search matches title, language, and tags.

3 · The quick panel

A floating panel over any app: search → select → retrieve. Keyboard-first.

Open & close

  • Open / close: ⌘⌥K (default, customizable — see the settings reference)
  • Close: esc, or click anywhere outside the panel
  • Works over any foreground app, fullscreen included; on multi-monitor setups it appears on the active screen

Search

  • Matches: title, language, tags
  • Recency-first: empty query shows “Recently used”; typing sorts by relevance
  • Type filter: chips at the top of the panel (All / Code / Prompt / Text / Key)
  • In the main window (not the quick panel), search is ⌘K

Double-click typing

Setting: main window → Settings → Type into field.

  • Off: double-clicking an item copies it; you paste with ⌘V yourself
  • On: if an editable text field was focused before you opened the panel (terminal, editor, chat box…), double-clicking writes the content straight into that field, keeping a copy on the clipboard

Great for pasting commands into terminals and templates into chat apps. Requires the Accessibility permission.

Custom container layouts

Search is the general path, but your ten most-used items deserve a faster route — containers pin them into a personal layout:

  1. Switch to the Custom tab on the right of the panel

  2. Click Edit → New Container, and title it (e.g. DB daily)

  3. Select items in the left-hand results and click Add to drop them into the current container

  4. Drag items to reorder within or across containers; drag a container's bottom-right corner to resize it

  5. Click Done. Browse mode shows a clean layout with editing controls hidden

  • Group one scenario per container (e.g. “deploy commands”, “go-to prompts”) — open the panel and click instead of searching
  • The top bar shows a layout summary: N containers · M snippets
  • Edit mode supports clearing and deleting individual containers; layout data syncs and backs up with your vault
Advice

Search first, containers second: run on search for a while; when you notice items you search for daily, pin them into a container. Recently-used ordering is already smart — no manual pinning needed.

4 · Items & the four types

The type determines fields and retrieval behavior — sorted the way technical workers actually own information.

Code代码

Function snippets, SQL, config templates, shell commands. Language-highlighted.

Prompt提示词

LLM prompts, email templates, canned replies. Grab and tweak.

Text笔记

Troubleshooting logs, environment notes, cheat sheets. Record the why.

Key密钥

API tokens, connection strings, internal endpoints. AES-GCM encrypted, masked.

A quick test: if you'll use it a second time, it belongs in the vault; templates you received but will send onward are Prompts; anything whose leak would hurt is a Key.

Fields

  • Title: the primary search target — favor prefix-retrievable names
  • Language: Code items only; drives highlighting in the editor and preview
  • Notes: context for your future self — where this came from, when to use it, gotchas
  • Tags: short words added with Return; the sidebar's tag section aggregates them for one-click filtering

Build your own short-tag system: db, deploy, llm, work… Avoid “two tags for one concept”.

The Key type & encryption

  • Sensitive fields of Key items are encrypted at rest with AES-GCM; keys are derived and managed by the app
  • Credentials and sync tokens live only in the Keychain, never in plain files
  • Key content is masked in panels and lists; retrieval works like any other item (copy / type)
  • Encryption protects data at rest: with sync enabled, ciphertext travels to your configured server
Security note

CodeVault does not replace secret rotation. Rotate production credentials regularly and enable FileVault — that beats any single tool.

Editor

  • Create and edit in the main window's editor, with a word-wrap toggle and language highlighting
  • For existing items: Save Changes applies; Discard reverts
  • Copy straight from item cards — no need to open the editor

6 · Multi-device sync

Local-first: without signing in it's a purely local app. Sign in and it auto-syncs every 5 minutes.

Sign in

Menu bar → Sign In, fill in two fields:

FieldDescription
Server addressThe sync endpoint, e.g. https://sync.example.com (official service or your own Worker)
API tokenAccess credential issued by the server; stored only in your local Keychain

Where the token comes from (either way): on the official service, register in the web portal → create an app → generate a token (shown once in plaintext); for self-hosting, you generate it during deployment — see the next chapter.

How sync works

After signing in, the app syncs every 5 minutes automatically, or instantly on demand:

# each sync = one read, one write; unchanged data skips the write
App ── GET  full dataset ──▶ server
App ◀── server's full set ───
        local merge (last-write-wins)
App ── POST merged result ─▶ server
  • Scope: vault items (title, type, language, content, notes, tags, container layouts)
  • Per-app limit 24 MiB — practically unreachable with text

Conflict rules (transparent & predictable)

SituationOutcome
Two devices edited different itemsBoth kept
Two devices edited the same itemNewer updatedAt wins (last-write-wins)
Deleted on one device, untouched on the otherDeletion applies
Deleted here, edited offline thereDeletes within 7 days carry tombstones — the item stays deleted
New Mac / reinstall

Sign in with the same server address + token: the first sync pulls the full set back to this machine — no manual migration. Signing out keeps local data and only stops syncing.

Token safety

If a token leaks: on the official service, revoke it in the portal; when self-hosting, reset the token (the old value dies instantly) — see Self-hosting, operations section.

7 · Self-hosting

Don't want any third-party sync service? Deploy the backend to your own Cloudflare account in 10 minutes.

What you get

  • A sync endpoint at https://<your-subdomain>.workers.dev (custom domains supported)
  • A global token you generate yourself: every device uses the same address + token pair
  • Storage on Cloudflare Workers KV — the free tier is plenty for personal multi-device use

Prerequisites

A Cloudflare account (free tier is fine) and Node.js locally (to run the wrangler CLI).

Six steps to deploy

# 1. enter the repo's sync-worker directory
cd sync-worker

# 2. install dependencies (wrangler CLI)
npm install

# 3. log in to Cloudflare (browser authorization)
npx wrangler login

# 4. create the KV namespace; paste the printed id into wrangler.toml
npx wrangler kv namespace create SNIPPETS

# 5. generate your token (write it down — shown only once)
openssl rand -hex 32

# 6. configure the token and deploy
npx wrangler secret put SYNC_TOKEN
npx wrangler deploy

Wrangler prints your endpoint when done. In the app: menu bar → Sign In → paste the domain as the server address and the step-5 token; use the same pair on every Mac.

Day-to-day operations

TaskCommand / note
Redeploynpx wrangler deploy after changes
Invalidate the old tokennpx wrangler secret put SYNC_TOKEN with a new value; update all devices
Local developmentcp .dev.vars.example .dev.vars && npm run dev → http://localhost:8787
Run testsnpm test (89 functional tests, local only)

Advanced: hosting for others (optional)

The same Worker supports a “service mode” for family / friends / teams:

  • Set ADMIN_PASS and GET / becomes a user portal (register / sign in / manage apps & tokens)
  • Set both RESEND_API_KEY + RESEND_FROM to enable email-verification signup
  • Admins can delete users from the portal (cascades across their apps, tokens, and data)

Full configuration and architecture: sync-worker/README.md and DEPLOY.md.

Limits & trade-offs

Per-app dataset limit 24 MiB (Workers KV value cap); conflicts resolve client-side by newest update — the server never parses content; Workers KV is eventually consistent (≤60s cross-node).
